## Yang Harus Dibuat atau Diperbaiki

Prioritas 0:
- Pasang dan kunci environment OMPL yang benar, lalu tambahkan smoke test import OMPL.
- Tambahkan `pytest.ini` atau konfigurasi test agar pytest tidak meng-collect `venv`.
- Buat test cepat yang menjalankan parser scene, planner init, dan log analyzer tanpa viewer.

Prioritas 1:
- Buat acceptance suite untuk `tidy_up` dengan skenario no-obstacle, obstacle, dual-arm, dan cube stacking. Kriteria pass harus `success=True` dan `objects_moved == objects_total`.
- Jalankan dan simpan log `tidy_up*`; saat ini belum ada bukti.
- Implementasikan cube stacking sungguhan: target Z bertingkat, stabilitas stack, collision/grasp/place validation untuk objek yang sudah ditumpuk.

Prioritas 2:
- Perbaiki bottleneck eksekusi: collision waypoint awal, IK error, grasp/lift failure, dan place accuracy.
- Tambahkan recovery pose yang tervalidasi setelah drop/place.
- Tambahkan grasp candidate sampler per object type dan per arm, bukan hanya retry grip/height.

Prioritas 3:
- Buat modul segmentasi trajectory eksplisit: representasi segment, input/output, evaluasi, dan log per segment.
- Tambahkan benchmark OMPL planner per segment: RRTConnect, RRTstar, BITstar, PRMstar, KPIECE1, EST dengan success rate, duration, path length, collision failure, dan scene variant.
- Baru setelah benchmark stabil, buat selector planner per segment berbasis data.

Prioritas 4:
- Definisikan dataset trajectory MuJoCo + OMPL yang lengkap: state, action/joint trajectory, phase/segment label, planner used, outcome, collision reason, IK error, object pose.
- Implementasikan trajectory refinement berbasis pengalaman sebelum RL.
- Jika tetap ingin RL, buat environment, reward, reset, termination, baseline, dan evaluasi 100% acceptance. Saat ini belum ada fondasi RL.
